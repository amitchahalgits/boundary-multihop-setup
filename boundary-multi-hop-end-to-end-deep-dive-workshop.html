2. Step-by-Step Setup Mechanics

Step 1 PostgreSQL Database & State Storage

What it does: Starts PostgreSQL 15 container listening on port 5432.

Under the hood: Boundary is stateless; all scopes, targets, hosts, credentials, and telemetry are stored encrypted inside PostgreSQL relational tables.

Step 2 AEAD KMS Cryptographic Keys (Root, Worker-Auth, Recovery)

What it does: Configures 3 distinct 256-bit AES-GCM encryption keys in controller.hcl:

  • purpose = "root": Encrypts database sensitive fields and Data Encryption Keys (DEKs) at rest.
  • purpose = "worker-auth": Shared trust anchor between Controller and Workers. Workers encrypt enrollment payloads with this key to achieve automatic Worker-Led trust.
  • purpose = "recovery": Break-glass key for emergency administrative access.
Step 3 Database Initialization (boundary database init)

What it does: Executes schema migrations, creates the root global scope, generates an initial administrative user/password, and outputs credentials to init.log.

Step 4 Ingress Worker Startup (Edge / DMZ)

What it does: Dials Controller cluster port (initial_upstreams = ["127.0.0.1:9201"]), completes node enrollment, and opens client proxy port 9202 with tag type=["ingress"].

Step 5 Egress Worker Startup & Multi-Hop DAG Formation

What it does: Starts internal VPC worker with initial_upstreams = ["127.0.0.1:9202"] (pointing to Ingress Worker proxy port).

Under the hood: When Egress dials Ingress, Boundary's routing engine constructs a Directed Acyclic Graph (DAG) establishing that Egress is downstream of Ingress.

Step 6 OpenSSH Target Container (Port Mapping 2222:2222)

What it does: Runs OpenSSH container listening on internal port 2222, mapped to host port 2222.

Step 7 Scopes, Host Sets & Static Credential Injection

What it does: Creates Org (DevOps Org) and Project (Core Infrastructure), registers Host Set pointing to 127.0.0.1, and stores injected credential (testuser:testpassword) inside a Static Credential Store using secure env:// syntax.

Step 8 Multi-Hop Target Creation & Binding

What it does: Creates Layer-7 SSH target with -ingress-worker-filter '"ingress" in "/tags/type"' and -egress-worker-filter '"egress" in "/tags/type"', then attaches destination host set and injected credentials.

3. Execution Trace: What Happens During boundary connect ssh

  1. Authorization: CLI requests session token from Controller (:9200). Controller verifies RBAC, loads injected credentials, and calculates worker path: [worker-ingress -> worker-egress].
  2. Handshake: Client dials Ingress Worker (:9202) with authorization token.
  3. Mesh Relay: Ingress Worker forwards encrypted stream across to Egress Worker (:9204).
  4. Injected Login: Egress Worker dials container (:2222), injects testuser:testpassword directly into the SSH handshake.
  5. Shell: Interactive PTY terminal opens with zero password prompts.

4. Team Dry-Run Troubleshooting Workshop (3 Layers)

Scenario 1: Ingress Layer Bug (Filter Tag Mismatch)
Error: server.(Repository).SelectSessionWorkers: error #133

Cause: Target filter -ingress-worker-filter '"public-dmz" in "/tags/env"' does not match worker's actual tag env=["dmz"].

Diagnosis: Compare boundary workers read tags with boundary targets read filter.

Fix: boundary targets update ssh -id $TARGET_ID -ingress-worker-filter '"dmz" in "/tags/env"'

Scenario 2: Egress Layer Bug (Broken Multi-Hop Mesh DAG)
Error: No ingress workers with valid next-hop paths could be found

Cause: Egress worker in worker-egress.hcl points to Controller (:9201) instead of Ingress Worker (:9202), preventing DAG path calculation.

Diagnosis: Both workers are active, but Controller cannot find a reachability path between them.

Fix: Set initial_upstreams = ["127.0.0.1:9202"] in worker-egress.hcl and restart worker.

Scenario 3: Target Layer Bug (Container Port Mismatch)
Error: Connection closed by 127.0.0.1 port <ephemeral>

Cause: Container runs with -p 2222:22 while sshd listens on 2222 inside container.

Diagnosis: Controller logs show route succeeded [w_ingress w_egress], but destination closes socket.

Fix: Re-run container with -p 2222:2222.
